# Quality Attribute Scenarios

Каждый сценарий описан шестью полями по SEI: **источник стимула → стимул → артефакт → окружение → реакция → мера реакции**. Мера реакции всегда измерима и ссылается на NFR из [nfr-registry.md](nfr-registry.md).

## QAS-1. Доступность: отказ группы отказа (стойки) во время флеш-распродажи

| Поле | Значение |
|-|-|
| Источник стимула | Инфраструктура локальной площадки в Лагосе |
| Стимул | Полностью недоступна одна группа отказа ячейки — стойка или фидер питания ЦОД-1 вместе с нодами приложения и primary PostgreSQL. В Нигерии это аналог AZ у локального оператора: hyperscaler-зон в стране нет ([cloud-regions-comparison](../Task4/cloud-regions-comparison.md)) |
| Артефакт | Страновая ячейка NG: приложение, PostgreSQL с синхронной репликой, Valkey |
| Окружение | Пик распродажи в неделю запуска, 5 000 одновременных сессий |
| Реакция | Kubernetes перезапускает поды на оставшихся нодах других стоек и в ЦОД-2. Реплика БД продвигается до primary автоматически. Клиенты повторяют запросы с ключом идемпотентности. Каталог продолжает отдаваться из CDN (stale-if-error) |
| Мера реакции | Путь заказа восстановлен ≤ 5 мин (NFR-07). Потеряно 0 подтверждённых заказов (RPO ≈ 0, NFR-06). Бюджет месяца (43 мин, NFR-01) израсходован не больше чем на 12 % |

## QAS-2. Задержка P99: открытие карточки товара по диплинку из рекламы

| Поле | Значение |
|-|-|
| Источник стимула | Покупатель, кликнувший рекламу в Facebook или TikTok (A2) |
| Стимул | Открывает диплинк на карточку товара |
| Артефакт | CDN → API каталога → Valkey → PostgreSQL |
| Окружение | Android < $150, 3G (1,6 Мбит/с, RTT 300 мс), нормальная нагрузка 1 000 RPS на origin |
| Реакция | CDN отдаёт JSON карточки и WebP-изображение нужного размера. При промахе API берёт карточку из Valkey (Cache-Aside), при промахе — из БД с прогревом кеша |
| Мера реакции | Серверное время p99 ≤ 800 мс, p95 ≤ 300 мс (NFR-09). Отрисовка карточки p75 ≤ 2 с, p95 ≤ 4 с (NFR-08). Вес ответа ≤ 150 КБ (NFR-13) |

## QAS-3. Пропускная способность: старт live-стрима

| Поле | Значение |
|-|-|
| Источник стимула | 50 000 зрителей стрима в пятницу 17.10 (A2, обещание 7) |
| Стимул | 10 % зрителей одновременно открывают показанный товар и пытаются купить в течение 10 минут |
| Артефакт | Каталог (чтения), модуль заказа и резервирования остатков, PSP |
| Окружение | Пик, автоскейлинг включён, видео идёт через внешний сервис (не наша нагрузка) |
| Реакция | Карточка товара прогрета в CDN заранее (event-based warm-up). Резервирование остатка — атомарный `UPDATE … WHERE stock > 0` в PostgreSQL. HPA добавляет реплики. Чтения каталога изолированы в отдельный deployment того же бинарника (bulkhead) и не забирают ресурсы у оформления заказа |
| Мера реакции | 10 000 RPS на edge при ≥ 90 % попаданий в CDN. 50 заказов/с без роста p99 оформления выше 1,5 с (NFR-10, NFR-11). 0 продаж сверх остатка. Проверено нагрузочным тестом ×10 за 2 недели до запуска |

## QAS-4. RTO/RPO: потеря площадки целиком

| Поле | Значение |
|-|-|
| Источник стимула | Отказ питания или связи всего ЦОДа в Найроби |
| Стимул | Ячейка KE недоступна полностью |
| Артефакт | Ячейка KE: приложение, PostgreSQL, бэкапы |
| Окружение | Рабочий день, Год 1 (холодный DR, ступень 99,9 %) |
| Реакция | Дежурный объявляет SEV1 и запускает runbook. ArgoCD разворачивает ячейку на резервной площадке в Кении. БД восстанавливается из непрерывного WAL-архива. Каталог продолжает отдаваться из CDN, покупатели видят «оформление временно недоступно» |
| Мера реакции | **RTO ≤ 4 ч, RPO ≤ 1 мин** (NFR-06, NFR-07) в Году 1. Год 2 (warm standby): RTO ≤ 30 мин. Учения раз в квартал, фактическое время записывается |

## QAS-5. Отказоустойчивость: M-Pesa не отвечает

| Поле | Значение |
|-|-|
| Источник стимула | Safaricom Daraja API |
| Стимул | 50 % вызовов STK Push заканчиваются таймаутом в течение 30 с |
| Артефакт | Платёжный оркестратор (модуль `payment`) |
| Окружение | Вечерний пик в Кении |
| Реакция | Circuit breaker размыкается. Новые платежи маршрутизируются через Flutterwave (сбор M-Pesa). Уже инициированные проверяются через Transaction Status API с повторами по экспоненте. Заказы принимаются со статусом «ожидает оплаты» |
| Мера реакции | Приём заказа остаётся ≥ 99,9 % (NFR-01, NFR-05). 0 двойных списаний (NFR-04). 0 расхождений сверки через 15 мин (NFR-03). Переключение ≤ 60 с |

## QAS-6. Переносимость: перенос ячейки к другому провайдеру

| Поле | Значение |
|-|-|
| Источник стимула | Решение совета директоров или требование регулятора разместиться on-prem |
| Стимул | Нужно развернуть ячейку NG на другом провайдере (из локального облака на собственное железо) |
| Артефакт | Манифесты GitOps, Terraform-модули, данные PostgreSQL |
| Окружение | Плановая миграция |
| Реакция | Создаётся Certified Kubernetes-кластер. ArgoCD применяет те же манифесты. Данные переносятся логической репликацией PostgreSQL. Объекты копируются по S3 API |
| Мера реакции | Ячейка поднята ≤ 1 рабочего дня, переключение трафика с простоем ≤ 15 мин. Изменения кода — 0 строк (NFR-15, NFR-19) |

## QAS-7. Работа без сети: покупатель теряет 3G

| Поле | Значение |
|-|-|
| Источник стимула | Мобильная сеть (K: 3G с частыми обрывами) |
| Стимул | Связь пропадает на 2 минуты во время оформления заказа |
| Артефакт | Мобильное приложение: офлайн-кеш, очередь запросов |
| Окружение | Пригород Лагоса, нормальная нагрузка |
| Реакция | Каталог и корзина работают из локального кеша. Запрос `POST /orders` хранится с ключом идемпотентности и повторяется при появлении сети. При необходимости статус приходит SMS |
| Мера реакции | 0 дублей заказа (NFR-04). Просмотренные карточки доступны офлайн (NFR-14). Заказ подтверждён ≤ 30 с после восстановления сети |

## Assumptions

- Пик запуска и live-стрима в QAS-1 и QAS-3 — 50 000 одновременных сессий: прогноз по умолчанию из Q4 Task1 (допущение при отсутствии ответа CEO).
- В QAS-3 доля зрителей, открывающих карточку и покупающих в течение 10 минут (10 %), — экспертная оценка по стрим-распродажам; проверяется замерами 17.10 и уточняет NFR-11.
- «Группа отказа» ячейки NG/KE — стойка или фидер питания в ЦОД локального оператора; AZ hyperscaler в Нигерии и Кении нет ([Task4/cloud-regions-comparison](../Task4/cloud-regions-comparison.md)).
