# SLO-контракт: Оплата (оформление заказа и платёж)

| Поле | Значение |
|-|-|
| Сервис | Модули `order` и `payment` монолита. Платёжный оркестратор поверх M-Pesa Daraja, Flutterwave, Paystack |
| Пользовательские пути | UC3 «Оформление заказа», UC4 «Оплата», UC12 «Выплата продавцу» |
| Владелец | Команда ядра. Дежурный — по ротации, реакция на page ≤ 15 мин |
| Потребители | Покупатели, продавцы (выплаты), CFO (сверка, издержки ≤ 2,5 % GMV) |
| Окно | 30 дней скользящее |
| Источник | NFR-01, 03, 04, 05, 06, 10, 27; A1 «Продавцы получают деньги», A7 «платить в тот же день», C-01, C-02, C-09 |

## SLI: что и как измеряется

Ключевое правило: **наш SLI не включает доступность PSP**. Если M-Pesa недоступна, заказ всё равно должен быть принят, а платёж уходит в очередь (C-02). Доступность партнёров измеряется отдельными SLI, чтобы видеть, кто отказал, и переключать маршрутизацию.

| SLI | Хорошие события / все события | Источник |
|-|-|-|
| **Приём заказа** | `POST /v1/orders` с ответом 2xx за ≤ 3 с (заказ создан, платёж инициирован или поставлен в очередь) / все валидные запросы | Prometheus |
| **Задержка приёма** | Запросы ≤ 1,5 с / все (p99) | Prometheus histogram |
| **Подтверждение оплаты** | Платежи, у которых статус стал финальным ≤ 60 с после callback PSP / все callback | Метрика `payment_finalized_seconds` |
| **Целостность денег** | Платежи, совпавшие при сверке с отчётом PSP за 15 мин / все платежи | Джоб сверки, ежечасно |
| **Выплата продавцу** | Выплаты, отправленные в день подтверждения доставки (до 23:59 местного) / все подтверждённые доставки | Метрика `payout_same_day_total` |
| Партнёр: успешность PSP (информационный) | Успешные вызовы API PSP / все — по каждому провайдеру и стране | Circuit breaker, Prometheus |

## SLO: целевые значения

| SLO | Цель (Год 1) | Бюджет ошибок за 30 дней | Год 2 |
|-|-|-|-|
| Приём заказа | **99,9 %** | 43,2 мин | 99,95 % |
| Задержка приёма p99 | ≤ 1,5 с | 1 % медленных | ≤ 1 с |
| Подтверждение оплаты ≤ 60 с | 99 % | 1 % | 99,5 % |
| Целостность денег | **100 %**, бюджета нет | 0 — любое расхождение = SEV1 | 100 % |
| Выплата в тот же день | 98 % | 2 % (выходные банков, сбой B2C) | 99 % |

## SLA: что гарантируется и что происходит при нарушении

| Кому | Что гарантируется | При нарушении |
|-|-|-|
| Инвестору и CEO | Заказы и платежи не теряются никогда. Путь заказа доступен 99,9 % (≤ 43 мин в месяц) | SEV1 и постмортем ≤ 48 ч. Повтор в квартал — пересмотр ступени доступности ([availability-strategy](../availability-strategy.md)) |
| Продавцам | Выплата в день подтверждения доставки, за вычетом резерва на возвраты (C-09) | Опоздание больше суток — комиссия платформы с заказа не взимается. Уведомление в WhatsApp с новым сроком |
| Покупателям | При двойном списании возврат инициируется автоматически ≤ 24 ч | Возврат плюс кредит на баланс. Учёт как SEV2 |
| CFO | Издержки PSP ≤ 2,5 % GMV (NFR-27) | Маршрутизация на более дешёвого PSP, отчёт CFO в течение недели |

**Что делаем, когда отказал партнёр:** circuit breaker размыкается после 50 % ошибок за 30 с. Новые платежи маршрутизируются на резервного PSP (NG: Flutterwave → Paystack; KE: M-Pesa Daraja → M-Pesa через Flutterwave). Если резерва нет, заказ создаётся со статусом «ожидает оплаты» и покупатель получает SMS со ссылкой оплатить позже.

## OpenSLO

```yaml
apiVersion: openslo/v1
kind: SLO
metadata:
  name: order-acceptance-availability
  displayName: Приём заказа — доступность
spec:
  service: payments
  budgetingMethod: Occurrences
  timeWindow:
    - duration: 30d
      isRolling: true
  indicator:
    metadata:
      name: order-accept-good-ratio
    spec:
      ratioMetric:
        counter: true
        good:
          metricSource:
            type: Prometheus
            spec:
              query: sum(rate(http_server_requests_total{route="/v1/orders",method="POST",code=~"2..",le_3s="true"}[5m]))
        total:
          metricSource:
            type: Prometheus
            spec:
              query: sum(rate(http_server_requests_total{route="/v1/orders",method="POST",code!~"4.."}[5m]))
  objectives:
    - displayName: order-acceptance
      target: 0.999
  alertPolicies:
    - fast-burn-page   # 14.4x за 1 ч и 5 мин → вызов дежурного
    - slow-burn-ticket # 6x за 6 ч и 30 мин → тикет
```

## Assumptions

- SLI приёма заказа намеренно исключает доступность PSP (C-02): партнёрские SLI отслеживаются отдельно и не влияют на наш SLO.
- «Выплата в тот же день» отсчитывается до 23:59 местного времени от подтверждённой доставки; банковские окна и сбои B2C укладываются в бюджет ошибок 2 % (SLO 98 %).
- Целостность денег (100 %) проверяется сверкой с окном 15 минут: расхождение, живущее дольше, — нарушение.
