# SLO-контракт: Уведомления (SMS, WhatsApp, push, USSD)

| Поле | Значение |
|-|-|
| Сервис | Модуль `notification` монолита: асинхронные воркеры, читающие outbox. Каналы - SMS/USSD-агрегатор, WhatsApp Business API (BSP), FCM/APNs |
| Пользовательские пути | Уведомления о заказе, оплате и доставке (UC3, UC11); команды продавцов в WhatsApp (UC9–UC11); статус по USSD (UC6, UC7) |
| Владелец | Команда ядра |
| Окно | 30 дней скользящее |
| Источник | NFR-05, NFR-23; A2 «пуш и SMS», C-08 (согласия); K (USSD, WhatsApp) |

## SLI: что и как измеряется

Уведомление измеряется в два этапа: «мы отдали провайдеру» - это зависит от нас, «провайдер доставил» - это зависит от оператора связи. SLO ставится на первый этап, второй отслеживается как SLI партнёра.

| SLI | Хорошие / все | Источник |
|-|-|-|
| **Своевременная передача** | Транзакционные уведомления, переданные провайдеру <= 60 с после события в outbox / все события | `notification_dispatch_seconds` |
| **Соответствие согласию** | Маркетинговые сообщения с действующей записью opt-in / все маркетинговые | Аудит-лог согласий |
| **Ответ USSD** | USSD-ответы, отданные шлюзу <= 2 с (сессия у оператора обрывается через ~20 с) / все запросы | Prometheus |
| **Обработка команды продавца** | Сообщения продавца в WhatsApp, на которые бот ответил <= 30 с / все | Webhook-метрики |
| Партнёр: доставка (информационный) | DLR «доставлено» <= 5 мин / отправленные - по каналу и оператору | DLR-callback агрегатора и BSP |

## SLO: целевые значения

| SLO | Цель | Бюджет за 30 дней |
|-|-|-|
| Своевременная передача <= 60 с | **99 %** | 1 % опоздавших (около 2 000 из ~200 000 в месяц на объёмах Года 1) |
| Соответствие согласию | **100 %**, бюджета нет | Любое нарушение - SEV1 (POPIA, NDPA) |
| Ответ USSD <= 2 с | 99,5 % | 0,5 % |
| Команды продавцов <= 30 с | 99 % | 1 % |
| Доставка партнёром (наблюдение) | >= 95 % <= 5 мин | - порог для переключения канала |

Доступность приёма событий наследуется от основного приложения: события пишутся в outbox той же транзакцией, что и заказ. Поэтому отдельный SLO доступности не нужен - потерять уведомление можно только вместе с заказом.

## SLA: что гарантируется и что происходит при нарушении

| Кому | Что гарантируется | При нарушении |
|-|-|-|
| Покупателю | SMS или WhatsApp о статусе заказа <= 5 мин в 95 % случаев. Маркетинг только после согласия | Нарушение согласия - SEV1, уведомление DPO, разбор в течение 72 ч (A3) |
| Продавцу | Новый заказ приходит в WhatsApp <= 2 мин | Доставка ниже 95 % - автоматический дубль по SMS |
| Бизнесу | Уведомления никогда не блокируют оформление заказа (bulkhead) | Постмортем при исчерпании бюджета |

**Деградация:** канал недоступен или DLR < 95 % за 15 мин → circuit breaker → резервный канал (WhatsApp → SMS, push → SMS). Агрегатор ограничивает частоту → очередь с повторами по экспоненте (1 с, 4 с, 16 с, до 15 мин), после 6 попыток - dead-letter и алерт.

## OpenSLO

```yaml
apiVersion: openslo/v1
kind: SLO
metadata:
  name: notification-dispatch-timeliness
  displayName: Уведомления - передача провайдеру <= 60 с
spec:
  service: notifications
  budgetingMethod: Occurrences
  timeWindow:
    - duration: 30d
      isRolling: true
  indicator:
    metadata:
      name: dispatch-under-60s
    spec:
      ratioMetric:
        counter: true
        good:
          metricSource:
            type: Prometheus
            spec:
              query: sum(rate(notification_dispatch_seconds_bucket{type="transactional",le="60"}[5m]))
        total:
          metricSource:
            type: Prometheus
            spec:
              query: sum(rate(notification_dispatch_seconds_count{type="transactional"}[5m]))
  objectives:
    - displayName: dispatch-60s
      target: 0.99
```

## Assumptions

- Объём Года 1 - около 200 000 уведомлений в месяц: 600 тыс. заказов в год ([tco-model](../../Task2/tco-model.xlsx)) × ~4 события на заказ.
- SLO ставится на этап «передано провайдеру <= 60 с»; доставка оператором - наблюдаемый партнёрский SLI, а не наше обязательство.
- USSD-сессия оператора живёт ~20 с; порог ответа 2 с оставляет запас на навигацию по меню и подтверждение.
